# ChemCritic 队友运行包

这是当前工作台的精简运行包，不是开发仓库备份。逐文件完整性以 MANIFEST.json 为准；本次改动清单见文末「本次修订记录」，其中固定引擎带有本地修订号并保留了上游原始哈希。

## 启动

1. 完整解压 ZIP，不要在压缩包内直接运行。
2. 使用 Python 3.11 或更新版本，在解压目录打开终端。如果已有可用的 httpx，无需安装。
3. 首次缺少依赖时运行 `python -m pip install -r requirements.txt`。
4. 运行 `python -m app.chemcritic.server --sciencepal --agent-mode research`。
5. 在终端隐藏输入自己获授权使用的 SciencePal 密钥，然后打开 http://127.0.0.1:8765/ 。不要把密钥发到聊天或写入文件。

保持终端开启；Ctrl+C 停止。端口占用可加 `--port 8766`，并打开对应地址。
无账号时可运行 `python -m app.chemcritic.server` 查看离线界面与本地规则，但不能调用共享 Agent。

## 判定范围（重要）

固定判定引擎只覆盖 Suzuki–Miyaura（芳基卤化物 + 硼酸/硼酸酯）。界面会实时显示“判定范围”（评估区一行，输入时随表单更新）：

- 属于该档案且角色齐备：运行固定引擎，给出可比性与档内定位。
- 其他反应：不运行引擎、不给可比性结论，只做事实整理、结果口径核对、证据缺口和用户自设目标的判断；
  下一步方案也限定为“该核查或补测什么”。
- 角色由用户在表单声明，系统不会从化学名称推断；不会把非 Suzuki 反应硬塞进芳基卤化物/硼酸字段。

新增反应家族的做法是加一个 `app/chemcritic/reaction_profiles.py` 档案（并在引擎支持时接入引擎），
记录格式与表单不需要改。

表单另有可选的「催化体系分类」五项（催化剂物理形态 / 配体族 / 载体 / 介质 / 活化方式），**只能由用户声明**，系统不根据催化剂名称推断。
五项齐全时引擎才能算出档位，`placement` 才可能从 `TIER_UNKNOWN` 变成 `PLACED`；任一项留空仍保持“无法判定”，并会在追问里列出缺哪几项。

## 产物结构证据（本次新增）

表单的“表征证据”表按行登记：表征方法、与目标是否一致、观测值原话、积分总数、实测 m/z、目标产物分子式、谱图/附件编号。
本地只用这些数值做算术核对：分子式 ↔ 氢数（核对积分总数）、分子式 ↔ 单同位素质量（核对 m/z，默认按 `[M+H]+`，可在记录中标注加合物）。
当前证据档位显示在评估区的「连接与任务信息」里（默认折叠，避免与报告正文重复），核对依据（例如“总积分 12H 与分子式氢数 12 一致”）也一并列出。

档位只回答“用户自己报的数据能被核对到什么程度”，不回答“这是不是目标产物”：

- 未提供表征证据 / 表征与目标矛盾：先补证据，恢复目标比较前不做数值结论。
- 只有结论（如“1H NMR 匹配”）而无观测值：仍是“用户报告匹配，未附数据”。
- 有观测值但缺分子式或参照：记为已记录、本地无法核对。
- 观测值与分子式经本地核对一致：可写“用户所报数据内部一致”，同时必须说明未经独立核验。
- 观测值自相矛盾：先核对抄录与加合物，不得沿用“结构已确认”。

这一档位不改变收率算术：数据矛盾时目标比较照常给出，但会同时进入 warnings 与优先核查项（`A05B_EVIDENCE_CONFLICT`）。

## 报告口径约定

引擎的 `placement` 只在“同口径 + 同底物对 + 同产物”的记录内定位；`classes`/`coverage` 是固定库按口径分组的全库统计。
两者读同一份 records，但分母不同，输出里分别给出 `same_pair_count`、`library_same_class_count`、`library_total_count`。
报告必须同时写出两个数，不能把“全库 19 条分离收率”写成“同口径下没有记录”或反之。

目标判断单独一条：页面评估区固定显示“按你所报数据：…”，这是本地规则按用户自报数值与自报口径算出的结果（只做加减，不含化学判断）。
报告正文若与它相反（例如本地算出未达到、正文写已达到），会标为待核查项，但**不改写报告正文**；口径不同或未设目标时显示“暂不能判断”。
文字输入模式没有本地结构化数值，该行不显示——这类模式的目标判断只能来自 Agent。

## 文件与数据

app/ 是工作台；cases/ 仅保留运行入口需要的示例与本地先例；deployment/ 保留被调用的固定程序；tools/agent_result_bridge.py 是远端执行桥接组件。
程序会自行创建 outputs/ 保存本机数据。运行中的 Agent 任务请先导出；密钥仅在进程内存中。
不附带原电脑的数据库、outputs、虚拟环境、测试历史、论文 PDF、临时附件、重复工程副本或 Git 历史。

新增模块：

- `app/chemcritic/schema_v2.py`：v0.2 通用记录校验与 v0.1→v0.2 升级。
- `app/chemcritic/reaction_profiles.py`：反应档案（角色 → 引擎字段）与“能否判定”的范围判定。
- `app/chemcritic/product_evidence.py`：产物结构证据分级与本地算术核对（积分 / 单同位素质量）。
- `tests/test_generic_record.py`：回归测试（升级等价性、范围判定、引擎分母、报告守卫、包哈希）。
- `tests/test_product_evidence.py`：证据分级、schema 往返与报告过度声明的守卫测试。

开发测试命令（本地，不调用 Agent）：

```
python -m unittest discover -s tests -v
python verify_package.py
```

MANIFEST.json 列出所有交付文件 SHA-256。运行 `python verify_package.py` 可离线核对文件；不调用 Agent。
包外的 acceptance.json 是本次干净目录验证记录，同机检查不能代替另一台电脑的环境与实际账户权限验收。
